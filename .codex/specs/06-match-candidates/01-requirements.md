## 1. Objective and Context

Compare the job description, required qualifications, responsibilities and "Nice to Have" content
described in the active job offer with the skills, and work experience from the candidate's resume.
Matching must account for semantic similarity and meaning-based relationships, in addition to exact
keyword matches.

## 2. Business Rules

- When searching for matching candidates, use the Vector Store embeddings as grounding data and
  let the LLM execute the matching.
- Candidate evidence sent to the LLM must come only from resume documents retrieved from the local
  Vector Store; candidate identities must be resolved from MongoDB records associated with those
  retrieved documents.
- The local Vector Store similarity threshold defaults to `0.6`; resumes below the threshold are
  not considered for matching.
- The default matching model is OpenAI `gpt-6-luna`. The model, API key, and similarity threshold
  must be configurable through application properties/environment-backed properties.

## 3. Functional Requirements

- The candidates matching is done by semantic similarity and meaning-based relationships,
  in addition to exact keyword matches.
- The selected job offer's description, required qualifications, responsibilities, and Nice to Have
  content are compared with retrieved resume evidence.
- Following Candidate information are to be taken into account:
    - Position
    - Technical Skills
    - Country
    - City
    - Working mode
    - Professional Experiences
- The model may rank only candidates represented by retrieved Vector Store documents. Candidate
  names and email addresses returned to the frontend are resolved from MongoDB, not generated by
  the model.
- The matching model receives the selected job criteria and retrieved resume evidence to perform
  the requested comparison.

## 4. Non-Functional Requirements

- Do not create, commit, or expose API credentials. Configure the OpenAI API key through an
  environment-backed application property; the recruiter can provide the key through deployment
  configuration later.
- OpenAI/model and similarity-threshold settings must be overrideable without code changes.

## Acceptance Criteria

### Scenario 1: Match candidates by semantic relevance and profile details

- **Given** the recruiter has selected a job offer and candidate resumes are indexed in the local
  Vector Store
- **When** they select **Find Candidates**
- **Then** the system matches candidates using semantic similarity and meaning-based relationships,
  in addition to exact keyword matches
- **And** the matching considers each candidate’s position, technical skills, country, city, working
  mode, and professional experience
- **And** only resume documents meeting the configured Vector Store similarity threshold are
  considered
- **And** candidate evidence used for matching comes from retrieved Vector Store resume documents
- **And** candidate identities shown in results are resolved from MongoDB documents associated with
  the retrieved resumes

### Scenario 2: Use configurable matching defaults

- **Given** the application starts without explicit candidate-matching overrides
- **When** a candidate search is performed
- **Then** the matching model defaults to `gpt-6-luna`
- **And** the Vector Store similarity threshold defaults to `0.6`
- **And** application properties can override the model, API key, and similarity threshold

### Scenario 4: Handling no matching results (Edge Case)

- **Given** the Vector Store is queried, but no indexed resumes meet the minimum semantic similarity
  threshold required for the job offer
- **When** the search is completed
- **Then** the system must not invent or hallucinate candidate profiles using an LLM
- **And** the system displays a clear message stating that no matching candidates were found for the
  current criteria, suggesting a review or loosening of the job qualifications
